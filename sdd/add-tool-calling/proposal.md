# add-tool-calling（新功能）

> MCP 支援的第一段。這段只把「模型呼叫工具 → 程式執行 → 結果回填 → 再問模型」的迴圈做通，
> 工具先用 DocSmith 內建的唯讀工具；接 MCP server（第二段）、工具授權設定（第三段）另外提案。

## 為什麼做

目前 AI 面板是單程的：`StartAIChat` 送一次 `/chat/completions`、串流收完就結束（`aichat.go`）。
模型只能看到使用者勾選帶進去的分頁內容，看不到資料夾裡的其他檔案，也沒有辦法自己去查。

MCP 的本質就是「給模型工具」，而它依賴的正是 OpenAI 相容介面的 tool calling（`tools` 參數、
`tool_calls` 回應、`role: "tool"` 回填）。這套迴圈 DocSmith 完全沒有，全專案搜不到 `tool_calls`。
先把迴圈做通，第二段接 MCP 時只是多一個工具來源。

同時這段要回答一個決定後續成敗的問題：**公司閘道吃不吃 `tools` 參數。** 閘道對 `reasoning_effort`
就曾直接回 400（見 `aichat.go` 的 `applyThinking` 註解），如果 `tools` 也一樣，第二、三段就不必做。

## 要改什麼

- **設定多一個「允許 AI 使用工具」開關**，每個供應商各自設定，預設關閉。
  關閉時送出的請求與現在完全相同，不帶 `tools`，舊閘道不受影響（沿用思考模式「未設定就不加參數」的做法）。
- **三個內建唯讀工具**，只能存取側邊欄目前開啟的資料夾：
  - `list_dir`：列出資料夾內容（沿用 `ListDir`）
  - `read_file`：讀取文字檔（沿用 `ReadFile`，過長時截斷）
  - `search_folder`：在資料夾內全文搜尋（沿用 `SearchFolder`）
  - 路徑一律解析後檢查必須在資料夾根目錄之內，`..`、絕對路徑、捷徑都不能逃出去。
  - 沒有開資料夾時不提供工具。
  - 這段**只給唯讀工具**，所以不需要執行前確認；會寫入的工具等第三段有授權設定再說。
- **對話改成多輪迴圈**（Go 端）：
  - 開關打開且有資料夾時，請求帶上 `tools`。
  - 串流時累積 `delta.tool_calls` 的分片（名稱、參數是一段一段來的）。
  - 模型要求呼叫工具時，執行後以 `role: "tool"` 回填，再送下一輪；直到模型給出一般回覆。
  - 最多 8 輪，超過就停下並顯示提示，避免模型無限呼叫。
  - 按「停止」一樣能中斷整個迴圈。
  - 中間的工具往返只存在這一次請求裡，不寫進對話紀錄；紀錄只留使用者問題與最終回覆（和現在一樣）。
- **DeepSeek 的思考內容要回傳**（實作第 6 條時查到的規定，2026-09-23 確認這一段就支援）：
  DeepSeek 在請求帶 `tools` 時，先前每則 assistant 訊息都必須附上 `reasoning_content`，否則回 400。
  只在「供應商是 DeepSeek 且這次帶了 tools」時：工具往返的 assistant 訊息附上該輪的思考內容，
  前端送出的歷史回覆也附上當初存下的思考內容。其他情況一律不送，請求與原本相同。
- **面板顯示工具呼叫**：新事件 `ai:tool`，回覆上方出現一行「🔧 搜尋資料夾：關鍵字」之類的說明，
  讓使用者知道模型不是卡住，而是在查東西。這幾行會跟著訊息存進紀錄。
- **閘道不支援時的錯誤要看得懂**：帶 `tools` 被回 400 / 422 時，錯誤訊息明確指出「這個服務不支援工具呼叫，
  請到設定關閉」，而不是丟一段原始 JSON。

## 影響範圍

要改的：

- `aichat.go` —— 主要改動：多輪迴圈、`tool_calls` 分片累積、`ai:tool` 事件、`StartAIChat` 多收資料夾根目錄。
- `ai.go` —— `AIProvider` / `AIProviderView` / `AISaveRequest` 加 `Tools` 欄位；`aiError` 辨識「不支援 tools」。
- `frontend/src/ai/settings.js` —— 工具開關。
- `frontend/src/ai/panel.js` —— 傳資料夾根目錄、接 `ai:tool`、顯示工具呼叫列；歷史回覆附上思考內容（給 DeepSeek）。
- `frontend/src/i18n.js` —— 開關、工具說明、錯誤訊息的繁中 / 英文字串。
- `frontend/src/style.css` —— 工具呼叫列樣式。

新增的：

- `tools.go` —— 三個內建工具的定義（JSON schema）、執行、路徑檢查。
- `tools_test.go` —— 路徑逃逸、`tool_calls` 分片累積的單元測試。

不會動到的：

- 對話紀錄格式（`chatstore.go`）不變，舊紀錄照常開啟。
- 開關關閉時，所有請求與 1.0.2 位元組層級相同。
- 不引入 MCP SDK，`go.mod` 不變。
