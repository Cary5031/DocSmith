# add-file-reload（新功能）

## 為什麼做

有使用者反映：檔案在 DocSmith 開著的時候，如果被其他程式改過（另一個編輯器、Git 切換分支、外部程式重新產生 PDF），DocSmith 沒辦法重讀。現在唯一的做法是關掉分頁再重新開，開過的游標、捲動位置都會不見。更麻煩的是，DocSmith 完全不會提醒，使用者可能看著舊內容、甚至存檔把別人的修改蓋掉。

使用者希望：

1. 有一個「重新載入」，按下去就把目前分頁換成磁碟上最新的內容。
2. 檔案被外部修改時，DocSmith 自己發現，跳視窗問要不要重新載入。

另外，現在 F5、Ctrl+R 被 `main.js` 攔下來、按了沒有任何反應（WebView 的整頁重整 Wails 本身已經關掉了）。大家習慣用這兩個鍵「重新整理」，正好拿來用。

## 要改什麼

### A. 手動重新載入

**觸發方式**

- 工具列「檔案」群組在「另存新檔」後面加一顆「重新載入」按鈕（`RefreshCw` 圖示）。
- 快捷鍵 F5、Ctrl+R：從「攔下來不做事」改成「重新載入目前分頁」。
- 只作用在目前的分頁。

**Markdown / 文字檔分頁**

- 先從磁碟重讀（沿用既有的 `ReadFile`）。讀不到（檔案已刪除、改名、變成二進位檔）就顯示錯誤，目前內容完全不動，也不會先問要不要捨棄。
- 分頁有未存檔的變更時，先跳確認：「重新載入會捨棄『檔名』未存檔的變更」，按鈕為「重新載入」「取消」，Esc 等於取消。
- 只替換有差異的範圍：把「自動排版」裡比對頭尾相同部分的那段邏輯抽成共用函式，兩邊一起用。這樣改動以外的地方游標、捲動位置都不會跳。
- 重讀後算是「已存檔」（不會短暫閃出未存檔記號），編碼、換行格式、BOM 跟著磁碟上的檔案更新，狀態列同步。
- 重新載入是獨立的一個復原步驟：按 Ctrl+Z 可以回到重讀前的內容（此時分頁會顯示未存檔，因為跟磁碟不同）。
- 內容跟磁碟一樣時，狀態列提示「檔案內容沒有變更」，不動文件；換過內容則提示「已重新載入」。
- Markdown 預覽、側欄大綱照現有的變更事件自動更新，不另外處理。

**PDF / 電子書分頁**

- 先確認檔案還在，不在就顯示錯誤，閱讀器保持原樣。
- 關掉原本的閱讀器、清空容器後重新開啟同一個檔案。
- PDF 重新開啟後回到原本的頁數與縮放比例。
- 電子書沿用既有的閱讀位置紀錄（關閉時會存位置，開啟時會讀回），回到原本的位置。
- 電子書內文在 iframe 裡，現在只會把 Ctrl 組合鍵轉給主程式；要讓 F5 也轉過去，焦點在書本內文時按 F5 才有效。

**其他**

- 未命名、從沒存過的分頁：狀態列提示「這個分頁還沒有存成檔案」。
- 重新載入進行中再按一次不會重複執行。

### B. 自動偵測外部修改

**怎麼偵測**

- Go 端新增 `FileStamp(path)`：回傳檔案的修改時間與大小（檔案不存在時回傳「不存在」）。用輪詢比對，不引入檔案監看套件，也不怕編輯器用「另存再改名」的方式存檔。
- 每個有路徑的分頁記住一份「最後已知狀態」：開檔、存檔（含另存新檔）、重新載入之後都更新。自己存檔不會被當成外部修改。
- 檢查時機（只檢查目前的分頁）：
  - DocSmith 視窗在前景時，每 2 秒一次；
  - 從其他程式切回 DocSmith 視窗時，立刻檢查；
  - 切換分頁時，檢查切過去的那個分頁（所以背景分頁被改過，會在切過去時提示）。
- DocSmith 不在前景時不檢查，免得外部程式改到一半就跳視窗；切回來時一次檢查最新結果。
- 「是否在前景」平常看 `document.hasFocus()`；焦點所在的電子書內文（iframe）被移除後它會一直是 false，所以這時再問 Go 端 `IsForeground()`（前景視窗是不是本程式）。重新載入閱讀器時也會先把焦點拉回主頁面。
- 有對話框開著、正在重新載入時跳過，下一輪再檢查。

**偵測到之後**

- Markdown / 文字檔：修改時間或大小變了，再讀一次內容跟「最後載入或存檔的內容」比對，一樣（例如只是被碰了一下時間）就默默更新狀態、不打擾。
- 內容真的不同（或是 PDF / 電子書的修改時間或大小變了），跳視窗：
  - 沒有未存檔變更：「『檔名』已在其他程式中被修改，要重新載入嗎？」
  - 有未存檔變更：同上，再加一句「重新載入會捨棄你在這裡未存檔的變更」。
  - 按鈕「重新載入」「保留目前內容」，Esc 等於保留。
- 選「重新載入」：走 A 的重新載入流程，不會再問第二次。
- 選「保留目前內容」：把最後已知狀態更新成磁碟上的現況，同一次修改不會一直跳；檔案之後又被改，才會再提示。之後想更新還是可以按 F5。
- 檔案被刪除或移走：不跳視窗（沒有東西可以載入）；檔案之後又出現且內容不同，才提示。

**這次不做**

- 一次重新載入所有分頁（背景分頁在切過去時才檢查、提示）。
- 操作手冊的文字與快捷鍵表（要更新的話另外做，屬於只改文件）。

## 影響範圍

要改的：

- `frontend/src/main.js`：主要改動。新增 `reloadActive()`，抽出差異範圍的共用函式（`formatActive()` 改用它），工具列加按鈕，修改 F5 / Ctrl+R 的處理；分頁記住最後已知狀態，加入偵測與提示視窗。
- `frontend/src/i18n.js`：新增按鈕名稱、確認與偵測提示視窗、狀態列提示、錯誤訊息（繁中、英文各一份）。
- `frontend/src/viewers/pdf.js`：重新開啟時保留頁數與縮放。
- `frontend/src/viewers/ebook.js`：iframe 內按 F5 也轉給主程式。
- `frontend/src/style.css`：工具列群組右側間距 6px → 4px。多了重新載入按鈕後，預設視窗寬度（1280）下 Markdown 分頁的工具列會擠成兩行，縮小間距後維持一行（PDF 分頁在 1.1.0 就是兩行，不變）。
- `files.go`：新增 `FileStamp(path)` 與 `IsForeground()`（沿用 `titlebar.go` 已有的 Win32 呼叫）。
- `frontend/wailsjs/go/main/App.js`、`App.d.ts`、`models.ts`：Wails 依 Go 端重新產生的綁定。

不會動到的：

- 既有的 `ReadFile`、`SaveFile` 不改，`/__doc` 也不動（已經設了 `Cache-Control: no-store`，重新開啟讀到的就是最新檔案）。
- 開檔、存檔、工作階段還原、自動備份的行為不變。

發布時照慣例用 `publish.ps1` 升版（新功能，建議 1.2.0）。
