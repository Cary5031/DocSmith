# ai-write-to-doc（新功能）

## 為什麼做

目前 AI 面板只有在兩種情況下，才會出現「把內容放進文件」的按鈕：

1. 訊息的 `mode` 是 `rewrite` 或 `newdoc` —— 而這兩種模式**只有上方「常用動作」按鈕會帶**；
2. 回覆裡含有程式碼區塊 —— 每個 `<pre>` 前面才掛一排小按鈕。

輸入框送出時寫死 `send(text, 'chat')`（`panel.js` 的 `submit()`），所以使用者自己打字問的任何問題，一律是 `chat` 模式。若模型又用純 Markdown 回答（沒包在程式碼區塊裡），上面兩個條件都不成立，整則回覆連一顆按鈕都沒有。

結果就是：輸入「請幫我產生一份符合現代化 AI 的指引提示詞」，AI 認真回覆了，但內容只能停在對話框裡，使用者得自己反白、複製、切到分頁再貼上。AI 面板變成「只能聊天」，失去撰寫文件的能力。

## 要改什麼

分兩塊，彼此獨立、互相補足：

**A. 每則回覆都有動作列**

- 助手訊息串流結束後，一律在訊息底部顯示一排動作：插入游標處、取代選取範圍、開成新分頁、複製。
- 動作套用的內容是「整則回覆」，但沿用既有的 `documentFrom()` 邏輯：模型若把整份文件包在程式碼區塊裡，就自動剝掉外層圍籬，不要把 ``` 一起寫進文件。
- 目前分頁不是可編輯的文件（PDF、電子書）時，「插入」「取代」兩顆鈕停用並附說明，不讓使用者按了沒反應。
- 已經是 `rewrite` / `newdoc` 模式的訊息，保留原本的「套用到文件（走差異比較）」「開成新分頁」主按鈕，動作列不重複提供同樣的鈕。
- 錯誤訊息、思考中的訊息不顯示動作列。

**B. 輸入框可以先指定模式**

- 送出鈕旁加一組三選一：對話 / 改寫文件 / 新文件，預設「對話」。
- 選「改寫文件」：送出時把「請輸出完整內容」的指示併進這次的問題，回覆結束後出現「套用到文件」，按了走既有的差異比較視窗。
- 選「新文件」：送出時要求只輸出 Markdown 文件，回覆結束後出現「開成新分頁」。
- 選擇會跟面板寬度一起記在 `ai.panel` 狀態裡，下次開啟沿用。
- 模式只影響「這一次送出」，不改變已經存在的對話訊息。

## 影響範圍

要改的：

- `frontend/src/ai/panel.js` —— 主要改動：動作列 renderer、`submit()` 帶模式、模式切換 UI、layout 狀態多一個欄位。
- `frontend/src/i18n.js` —— 新增模式切換與提示用字串（繁中、英文各一份）。
- `frontend/src/style.css` —— 動作列與模式切換的樣式。

不會動到的：

- Go 端（`ai.go`、`aichat.go`）不動，送出的請求格式不變。
- `diff.js`、`conversations.js`、`history.js` 不動。
- 既有的「常用動作」七顆按鈕行為不變。
