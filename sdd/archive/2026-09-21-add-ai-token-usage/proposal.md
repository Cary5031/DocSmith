# add-ai-token-usage（新功能）

> 這是兩份提案中的第二份：**token 用量顯示與上限**。
> 要先做完 `sdd/add-ai-conversations/`（多組對話），這份才有「換一組」可以建議。

## 為什麼做

使用者看不到下一次請求會送出多少內容，不知道對話什麼時候該換一組；等到服務回報超過 context 長度才發現就太晚了。

## 要改什麼

### 1. 面板底部的用量長條

- 位置：AI 面板底部、輸入框上方，一條細長條加一行文字：`12,300 / 128,000 tokens（10%）`
- 長條代表**下一次請求會送出的量**：系統提示 ＋ 勾選的參考文件 ＋ 歷史 ＋ 輸入框裡的問題
  （勾一份長文件，數字會立刻變大；這正是「會不會超過模型 context」的指標）
- **實際值優先**：服務串流結尾若回報 `usage`，就用實際的 prompt tokens 校正估算係數；沒有回報時顯示估算值，文字前加「約」
- 估算方式：中文約 1 token ≈ 1.5 字、英數約 1 token ≈ 4 字元
- **顏色分級**：60% 以下正常、60~80% 轉黃、**80% 以上轉紅**，並在旁邊顯示「建議開新對話」（點了就等於按「新對話」）

### 2. 對話長度上限（分母）

- 先**依模型名稱自動判斷**常見模型的 context 大小（gpt-5.x / claude / gemini / deepseek…），判斷不出來用 128000
- AI 設定新增「對話長度上限」欄位可**手動覆寫**，每個供應商各自記；留空＝自動判斷
- 這個值只用來算百分比與提醒，**不會擋住送出**

## 影響範圍

- `aichat.go`（解析串流結尾的 `usage`，以 `ai:usage` 事件送前端）
- `ai.go`（供應商設定多一個 `contextLimit`）
- `frontend/src/ai/tokens.js`（新增：估算、模型 context 對照表、校正係數）
- `frontend/src/ai/panel.js`（用量長條、輸入時即時更新）
- `frontend/src/ai/settings.js`（上限欄位）
- `frontend/src/i18n.js`、`frontend/src/style.css`

## 不做什麼

- 不做費用（金額）估算：各家計價不同、公司閘道也未必照原價，算出來容易誤導
- 不自動截斷歷史、不自動開新對話
